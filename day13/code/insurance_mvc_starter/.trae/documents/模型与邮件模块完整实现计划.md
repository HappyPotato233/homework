## 五、关键设计决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 是否创建 services 层 | 是 | 用户明确要求"按分层架构（表现层路由、service 业务层、utils 工具层、core 基础设施层）"；ML 训练/LLM 调用逻辑复杂，不宜放在路由层 |
| OperationLog 是否实现 | 创建模型 + 在关键操作中记录 | API 文档 5.1 定义了 action 枚举值包含 model_training / email_generation 等，说明这些操作应记录日志。日志查询路由不在本次范围 |
| 模型文件存储位置 | `data/models/{model_name}.joblib` | 技术框架方案明确指定 |
| LLM 未配置时的行为 | 邮件生成 status=failed | API 文档 4.2 明确说明"未配置 LLM_API_KEY 时 status=failed" |
| predict_upload 是否入库 | 不入库，直接返回预测结果 | API 文档 3.5 明确说明"直接返回预测结果，不入库" |
| 训练时 is_best 重置 | 训练前清除所有旧 is_best 标记，训练后按 roc_auc 选最佳 | 保证每次训练后只有一个 best |
| 特征工程位置 | 封装在 ml_service._prepare_features 中 | 纯函数，可被 train/predict/predict_upload 复用 |
